# Панель Taro Aurum

Отдельный сайт со статистикой и карточками пользователей. Тот же бэкенд,
что у мини-приложения, только админские эндпойнты `/api/admin/*`.

**Живой адрес:** https://admin.taroaurum.online (Cloudflare Pages, проект
`taro-admin`, к git не подключён — выкатывается вручную).

```
npm run dev      # localhost:5174
npm run build
npm run deploy   # сборка + wrangler pages deploy --branch main
```

## Как устроен вход

Пароля нет. Кто администратор — решает `ADMIN_TELEGRAM_IDS` на бэкенде, то
есть список идентификаторов Telegram. Заводить рядом отдельный пароль
значило бы завести второй способ попасть внутрь и второе место, откуда его
можно украсть.

Вход идёт по OpenID Connect. Изначально здесь был классический виджет
Telegram — скрипт рисовал кнопку и отдавал данные, подписанные токеном
бота. Telegram его отключил: кнопка ещё рисуется, но на попытку
авторизации `oauth.telegram.org` отвечает словом `deprecated`.

Поток проходит через бэкенд, и это вынужденно: Telegram принимает обмен
кода на токен только вместе с секретом клиента
(`token_endpoint_auth_methods_supported` — только `client_secret_*`), а
секрету в браузере не место.

```
панель   →  GET /api/admin/oauth/start
                бэкенд запоминает state и code_verifier (PKCE),
                отправляет браузер на oauth.telegram.org/auth
Telegram →  GET /api/admin/oauth/callback?code=…&state=…
                бэкенд меняет код на id_token, проверяет issuer,
                audience и срок, сверяет sub с ADMIN_TELEGRAM_IDS
                и возвращает браузер в панель с пропуском во фрагменте
```

Пропуск (`app/admin_session.py`) — подписанная строка вида
`<id>.<истекает>.<подпись>`, живёт сутки. Сессий на сервере нет,
перезапуск бэкенда никого не разлогинивает. Панель хранит пропуск в
`localStorage` и шлёт заголовком `X-Admin-Session`.

Приходит пропуск во фрагменте адреса (после `#`), а не в параметрах:
фрагмент не уходит на сервер и не попадает ни в логи веб-сервера, ни в
`Referer`. Панель сразу вычищает его из адресной строки.

Подпись `id_token` не проверяется, и это осознанно: токен приходит прямым
ответом token-эндпойнта на наш запрос по TLS, подтверждённый секретом
клиента. Спецификация OIDC (§3.1.3.7) в такой ситуации прямо разрешает
опираться на TLS вместо подписи. Если токен когда-нибудь начнёт приходить
через редирект браузера — проверка подписи станет обязательной.

## Что нужно настроить один раз

| Где | Что |
|---|---|
| Настройки бота → Login Widget | **Redirect URI**: `https://taro-bot1-production.up.railway.app/api/admin/oauth/callback` — Telegram сверяет строкой, символ в символ |
| Настройки бота → Login Widget | **Trusted Origin**: `https://admin.taroaurum.online` |
| Cloudflare Pages | проект `taro-admin` → Custom domains → `admin.taroaurum.online` |
| Railway | `TELEGRAM_OAUTH_CLIENT_ID`, `TELEGRAM_OAUTH_CLIENT_SECRET`, `ADMIN_PANEL_URL`, `BACKEND_PUBLIC_URL` |
| Railway | `FRONTEND_ORIGINS` — адрес панели рядом с адресом мини-приложения, через запятую |

`Client ID` и `Client Secret` берутся там же, в разделе Login Widget.

## Переменные сборки

| Переменная | Зачем |
|---|---|
| `VITE_API_BASE_URL` | адрес бэкенда |

Задана в `.env.production`. При переезде бэкенда меняется она и
`BACKEND_PUBLIC_URL` на сервере — и обе должны совпасть с Redirect URI в
настройках бота.

## Чего здесь нет намеренно

Только чтение. Ни выдачи подписок, ни начисления энергии, ни удаления —
админские эндпойнты на бэкенде тоже только читают. Появится потребность
что-то менять — это отдельное решение: любая изменяющая ручка означает,
что украденный пропуск позволяет не только смотреть.
