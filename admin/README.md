# Панель Taro Aurum

Отдельный сайт со статистикой и карточками пользователей. Тот же бэкенд,
что у мини-приложения, только админские эндпойнты `/api/admin/*`.

**Живой адрес:** https://admin.taroaurum.online (Cloudflare Pages, проект
`taro-admin`, к git не подключён — выкатывается вручную).

```
npm run dev      # localhost:5174
npm run build
npm run deploy   # сборка + wrangler pages deploy --branch main
```

## Как устроен вход

Пароля нет. Кто администратор — решает `ADMIN_TELEGRAM_IDS` на бэкенде, то
есть список идентификаторов Telegram. Заводить рядом отдельный пароль
значило бы завести второй способ попасть внутрь и второе место, откуда его
можно украсть.

Вход идёт через виджет Telegram Login. Он отдаёт данные о вошедшем,
подписанные токеном бота. Панель кладёт их в `localStorage` и прикладывает
к каждому запросу заголовком `X-Telegram-Login-Data`, а бэкенд каждый раз
проверяет подпись заново (`app/telegram/auth.py::validate_login_widget`).
Сессии на сервере нет — сервер о входе не хранит ничего.

Схема подписи здесь **не та же**, что у мини-приложения: у виджета секрет
это SHA-256 от токена бота, а у `initData` — HMAC от строки `WebAppData`.
Перепутать легко, и тогда подпись не сойдётся ни при каких данных.

Подписанные данные живут сутки — ограничение стоит на бэкенде. Это пропуск
на предъявителя, и бессрочным он быть не должен.

## Что нужно настроить один раз

| Где | Что |
|---|---|
| BotFather | `/setdomain` для `@taroaurumbot` → `admin.taroaurum.online`. Без этого виджет не покажет кнопку входа. |
| Cloudflare Pages | проект `taro-admin` → Custom domains → `admin.taroaurum.online` |
| Railway | `FRONTEND_ORIGINS` должен содержать `https://admin.taroaurum.online` рядом с адресом мини-приложения, через запятую |

## Переменные сборки

| Переменная | Зачем |
|---|---|
| `VITE_API_BASE_URL` | адрес бэкенда |
| `VITE_BOT_USERNAME` | имя бота для виджета входа, без `@` |

Заданы в `.env.production`. При переезде бэкенда на другой хостинг меняется
первая — и пересборка.

## Чего здесь нет намеренно

Только чтение. Ни выдачи подписок, ни начисления энергии, ни удаления —
админские эндпойнты на бэкенде тоже только читают. Появится потребность
что-то менять — это отдельное решение: любая изменяющая ручка в панели
означает, что украденный пропуск позволяет не только смотреть.
